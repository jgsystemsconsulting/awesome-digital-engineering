# Security Policy

## Supported

This repository is a curated list, not an application. The supported surface is this
repository itself: its content, its workflows, and the links it lists. There is no
supported-versions table because there is no shipped executable product.

## Reporting a vulnerability

Use GitHub private vulnerability reporting on this repository: open the Security tab
and choose "Report a vulnerability", or open a private advisory at
https://github.com/jgsystemsconsulting/awesome-digital-engineering/security/advisories/new.

Do not open a public issue for a security report. A pull request that only removes a
malicious link may be used after private triage when the maintainer asks for one.

Two report types are in scope:

- A listed link that has turned malicious, compromised, hijacked, or serves content
  materially different from its description.
- A vulnerability in this repository itself (workflows, scripts, repository
  configuration).

## Response expectations

Reports are acknowledged within 5 business days. Removal or fix is prioritized by
exposure, and a public note follows after remediation when appropriate.

## Out of scope

Vulnerabilities inside the tools the list links to. Those belong to the linked
projects' own security channels; this repository only acts on the entry.
